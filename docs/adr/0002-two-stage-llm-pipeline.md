# Two-stage LLM pipeline with per-item processing

Every 8-K runs through a cheap first-stage model that classifies Importance (1–5) and identifies Items; only Importance ≥4 (plus rule-based high-value Items like 1.01/2.01/5.02) proceed to an expensive second-stage model that produces the full structured card (Long-term View, Common Misreading, Impact Dimensions). 10-K/10-Q are split by Item via XBRL structure: high-value Items (1A, 7, 7A) get deep summaries including year-over-year diffs; mid-value Items get a one-line summary from the cheap model; low-value Items are dropped. Rejected alternatives: running the expensive model on everything (cost prohibitive at 10-K scale, ~$2–10/filing); running only the cheap model (loses the differentiated Long-term View and Common Misreading quality that define the product). The two-stage split is also what makes per-user cost tractable under the unified server-side billing model.
