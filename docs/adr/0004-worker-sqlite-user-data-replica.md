# User-private data mirrored to worker SQLite as a read-replica

The worker needs two pieces of user-private data to do its job: APNs device tokens (to push the daily digest) and Watchlist CIKs (to scope EDGAR ingestion and LLM cost). CloudKit Server-to-Server access to Private DB is per-user (requires an in-app OAuth flow and per-user token management) — disproportionate engineering for a single-developer MVP. Instead, the app POSTs device tokens and Watchlist changes to a minimal FastAPI endpoint on the worker, which stores them in SQLite. CloudKit Private DB remains the source of truth that the user sees and edits; the worker SQLite is a processing-only read-replica. Consistency is maintained by upsert-on-change plus a weekly full-sync from the app to correct drift; missed CIKs are backfilled by the gap-detection cron re-pulling recent daily indexes (EDGAR filings are permanently retrievable by Accession Number). This is the same pattern used for device tokens, keeping the worker's user-data interface uniform.
