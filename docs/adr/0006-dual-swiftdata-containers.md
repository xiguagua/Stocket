# Separate SwiftData schemas/configurations: user-private + local-only reference data

The app separates user-private models from reference data with distinct SwiftData schemas/configurations. User-private models (UserTicker, ReadState, NotificationPref, DigestViewPref) are eligible for CloudKit Private DB sync so user state can follow the user across devices. Reference data (EventSummary, TickerMeta) is a local-only mirror of shared data pulled from the Cloudflare Worker; it must not touch CloudKit, which keeps shared data out of the user's Private DB quota and avoids treating shared reference data as user-owned state. These schemas/configurations can be hosted by one `ModelContainer`; do not split containers unless there is a concrete need. Rejected alternatives: a single CloudKit-backed configuration for all models (shared data would pollute the user's Private DB or create incorrect ownership semantics); a single local-only configuration with manual CloudKit sync (loses SwiftData's native CloudKit integration for data that actually needs it). The trade-off is configuration discipline: new models must be assigned to the correct schema/configuration based on ownership, sync needs, and lifecycle.
