# Dual SwiftData containers: CloudKit-synced private + local-only shared

The app uses two SwiftData containers with different sync strategies. `UserContainer` holds user-private models (UserTicker, ReadState, NotificationPref, DigestViewPref) and is backed by CloudKit Private DB for multi-device sync. `ReferenceContainer` holds a read-only mirror of shared data (EventSummary, TickerMeta) pulled from the Cloudflare Worker and is local-only — it never touches CloudKit, keeping shared data out of the user's Private DB quota and avoiding split sync semantics within a single container. Rejected alternatives: a single CloudKit-backed container (shared data would either pollute the user's Private DB or fail to sync, and SwiftData's CloudKit sync is container-level all-or-nothing, not per-model); a single local-only container with manual CloudKit sync (loses SwiftData's native CloudKit integration for the data that actually needs it). The trade-off is a split data-access layer in the app — `@Environment(\.modelContext)` must be targeted to the right container — which is accepted because the two data classes have different ownership, sync needs, and lifecycles.
