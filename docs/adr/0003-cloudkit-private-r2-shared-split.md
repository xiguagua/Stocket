# CloudKit Private DB for user data, Cloudflare R2 + Worker for shared data

User-private data (Watchlist, read state, notification preferences) is stored in CloudKit Private DB as the source of truth, synced across the user's devices via CloudKit. Shared, deduplicated data (filing summaries, event cards, ticker metadata) is stored in Cloudflare R2 as JSON objects, served to the app via a stateless Cloudflare Worker read endpoint. The app uses two SwiftData containers: one backed by CloudKit (private data), one local-only (a read mirror of shared data for offline browsing). Rejected alternatives: CloudKit Public DB for shared data (requires hand-rolled ES256 JWT server-to-server signing in Python, and hits Public DB record limits faster); a single self-hosted backend with its own database (duplicates CloudKit's sync/offline/multi-device story and adds an auth system the MVP doesn't need). The trade-off is a split data-access layer in the app (CKContainer for private, HTTP for shared), which is accepted because the two data classes have different semantics anyway.
